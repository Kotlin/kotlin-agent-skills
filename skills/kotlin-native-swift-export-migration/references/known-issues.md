# Known issues by version

These are specific to the versions in the "verified on" column. **Newer releases may have fixed them.** Check the
latest releases first (SKILL.md Phase 1 step 1). Then search this file for the exact error text. If a fix here
names a version, prefer a newer one that you checked is published.

General rules (unsupported constructs, hiding, umbrella module) live in SKILL.md and the other references. This
file only holds facts that change from version to version.

## Swift Export build (Phase 3)

All the library failures below happen only when the library is **exported in full**, i.e. it is a direct `api`
dependency of the module that has `xcodeIntegration()`. The fix is the `:ios-export` umbrella module (SKILL.md
Phase 2). Through an umbrella, none of them needed hiding (PeopleInSpace: SQLDelight + Koin + coroutines +
serialization + lifecycle). Hide a library only if it still fails through the umbrella
(`hiding-broken-dependencies.md`).

| Symptom (exact error text) | Cause | Fix | Verified on |
|---|---|---|---|
| `OrgJetbrainsKotlinxKotlinxCoroutinesCore.kt: ... Argument type mismatch: actual type is 'MutableMap<Any?, Any?>'` (coroutines `groupByTo`) | kotlinx-coroutines-core is a direct `api` dep of the exporting module (plugins add it too, e.g. kotlin-native-nuget adds it to `nativeMainApi`) | umbrella module. **Never hide coroutines**: every `Flow`/`StateFlow` in your API then fails with `does not conform to expected type 'KotlinStateFlow'`. Don't hand-write a callback-only Swift API around it either | Kotlin 2.5.0-RC2, coroutines 1.11.0, 2026-11 |

## Xcode / Swift (Phases 2, 5, 6)

| Symptom (exact error text) | Cause | Fix | Verified on |
|---|---|---|---|
| `cannot find type 'KotlinBase' in scope` | the generated `<Module>.swift` imports `KotlinRuntime` without `@_exported` (`ExportedKotlinPackages` and `KotlinCoroutineSupport` *are* re-exported) | `import KotlinRuntime` in every Swift file that names `KotlinBase`. Check the first lines of the generated file to see what is `@_exported` in your version | Kotlin 2.5.0-RC2, 2026-11 |
| `Undefined symbols for architecture arm64: "_sqlite3_..."` at link time | the ObjC framework linked SQLite for SQLDelight's native driver; the Swift Export static library doesn't | add `-lsqlite3` to `OTHER_LDFLAGS` of every app target | Kotlin 2.5.0-RC2, SQLDelight 2.4.1, 2026-11 |
| App aborts at runtime in `KotlinFlowIterator.next()` (`KotlinCoroutineSupport.swift`, the `as! Element` cast): `Could not cast value of type 'KotlinRuntimeSupport._KotlinExistential<__C.Kotlin_kobjc...>' to '...ExportedKotlinPackages.<pkg>.<YourEnum>'`. Compiles fine; also when reading `StateFlow.value` of such a type | **KT-90088**: a Kotlin enum as an element of a `List`/`Map`/`Set` (or nested, e.g. `Flow<List<List<LetterStatus>>>`) isn't bridged to the Swift enum. Enums returned directly (`fun statusAt(...): LetterStatus`) work | expose the collection in an enum-free shape for Swift: e.g. a parallel `StateFlow<List<List<Int>>>` of ordinals mapped back with `MyEnum(rawValue:)`, or per-element accessor functions returning the enum plus a version/tick `StateFlow<Int>` that SwiftUI observes. Keep the enum flows for Android/desktop. Re-test on newer Kotlin and drop the workaround once fixed | Kotlin 2.5.0-Beta2 and 2.5.0-RC2, 2026-11 |
| Warning `cast from 'kotlin.collections.ArrayList' to unrelated type '[[T]]' always fails` | a public Kotlin `ArrayList<T>` (also `HashMap`, `LinkedHashMap`, ...) exports as an opaque class, not a Swift array/dictionary | declare `List<T>` / `Map<K, V>` in the public signature (the value can stay an `ArrayList`) | Kotlin 2.5.0-RC2, 2026-11 |
| A property with both `@NativeCoroutines` and `@HiddenFromObjC` still appears in the generated Swift | in KMP-NC compatibility mode the plugin clones the annotated declaration and Swift Export publishes the clone under the original name; `@HiddenFromObjC` only hides the original | usually no need to hide: just stop using it from Swift. | `./gradlew <EXPORT_MODULE>:tasks` (e.g. `:ios-export:tasks`, or another CLI call on the umbrella) fails: `Failed to apply plugin 'org.jetbrains.kotlin.multiplatform'. > Gradle#projectsEvaluated(Action) on build ':' ...` | `org.gradle.configureondemand=true` in `gradle.properties` | add `--no-configure-on-demand` to **that command-line call only**.
